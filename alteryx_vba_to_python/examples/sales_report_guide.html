How to read this

  • Containers are the boxes Designer draws around groups of tools. They are numbered 1, 2, 3… in the order they run. Each starts with the files it opens and saves: file › sheet › first row or cells.
  • Opening a file: in Alteryx every file read is its own tool box. Here it is shown inside the step that uses it ("matches its rows with Config.xlsm › sheet Clients on [ID]"); only a file that starts a flow of rows gets its own row ("opens …").
  • Branches: inside a container, the rows flow along branches. A branch is a chain of tools with no split or merge in it; it is named after its first tool's note or its filter test. Branch 3.4 is the 4th branch of container 3.
  • Steps: each branch is one table, a row per tool as it sits on the canvas: step number (3.14 is step 14 of container 3), the tool's name in Designer and its note, what it does, the columns it adds or changes, and the next step. A filter's outputs are T (true) and F (false); a join's are J (matched), L (left rows with no match) and R (right rows with no match). An output that nothing uses is dropped.
  • Under each table, one folded line per step holds its full rule (when … → … lines are read top down; the first true condition gives the value) and the same step in pandas, to paste into the steps notebook: df is the table flowing through the branch, s2_7 is step 2.7's output and s2_7_true its True output; src_… is a file as loaded in the notebook's Load cell, and FOLDER the workflow's folder. It also says whether the generated code converts the step exactly and names its function. ⚠ marks a step that is not converted.

def empty(s):
    """Alteryx IsEmpty: null or the empty string."""
    return s.isna() | (s == "")

def eq(a, b):
    """Alteryx "=": text is compared ignoring case; null equals null."""
    fold = lambda x: x.str.casefold() if isinstance(x, pd.Series) and x.dtype == object else (
        x.casefold() if isinstance(x, str) else x)
    null = lambda x: x.isna() if isinstance(x, pd.Series) else x is None
    return (fold(a) == fold(b)) | (null(a) & null(b))

Before relying on this

  • Alteryx behaviours the Python assumes (steps refer to them as A1, A2…; settle them once with the probe workflow):
    • A1 — Cleanse: the check-box numbers are mapped to options from memory of the standard macro; confirm against Cleanse.yxmc
    • A2 — DateTime: English only; output type for a date-only format is assumed to be Date
    • A3 — Input: column types depend on Alteryx's file driver; the types recorded in the workflow are applied when present
    • A4 — Join: row order of the three outputs and null = null on keys are not documented
    • A5 — Output: cell formats written by Alteryx are not reproduced; writes only with Context(write=True)
    • A6 — Sort: position of nulls and the order of upper/lower case are not documented
    • A7 — Summarize: output order, Sum of no values and Concat of empty values are not documented
    • A8 — Union: the type chosen when inputs disagree, and the order of the inputs, are not documented
    • A9 — Unique: output order is assumed to be the input order
